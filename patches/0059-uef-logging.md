# 0059 - what kernelbase's UnhandledExceptionFilter does with a breakpoint (diagnostic)

0.50.103 log: the filter of the covering `__try/__except` scope is the CRT's `_XcptFilter` (code from `[ecx]` = ExceptionCode, `call` into the CRT table lookup; it answers continue-search for a breakpoint, as on Windows), and then ntdll's `call_unhandled_exception_filter` calls kernelbase's UnhandledExceptionFilter which returns 1 (EXECUTE_HANDLER) -> `NtTerminateProcess(0x80000003)`. On Windows the game's own filter (SetUnhandledExceptionFilter) is where Arxan-style int3 handling usually lives. `dlls/kernelbase/debug.c`: `[uef] 0059 SetUnhandledExceptionFilter <new> (was <old>)`, `[uef] 0059 UnhandledExceptionFilter code= at ...: top_filter= nested=`, `[uef] 0059 top_filter <p> returned N`. Rebuilt with `DEST=/tmp/kb bash vendor/Madeira/build/wine-pe/build-modules.sh kernelbase` and copied to `vendor/Madeira/app/Madeira/arm64ec-windows/kernelbase.dll` (backup `$F4_BUILD_ROOT/backup-kernelbase-before-0059.dll`).

**0.50.104 result and 0060 (0.50.105).** The game DOES set a filter (`[uef] 0059 SetUnhandledExceptionFilter 0x705B7CB2C8`, blackops3 image, on its main thread) and kernelbase calls it for the breakpoint (`UnhandledExceptionFilter code=80000003 ... top_filter=0x705B7CB2C8`), and it returns 0 (EXCEPTION_CONTINUE_SEARCH), after which Wine's default path answers 1 and the process is terminated. On Windows it must return -1 (continue execution). 0060 dumps the filter's code blocks once (`[uef-dump] 0060 block <addr>: <hex>`, up to 140), the exception record (0x98 bytes) and the context's main registers at that call.
