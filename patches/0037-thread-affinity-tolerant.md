# 0037 - SetThreadAffinityMask no longer fails for a mask the system does not have (CS2 crash)

**Problem.** Counter-Strike 2 died after ~100 s in `embree3.dll+0x1bec` on every run, with or without `-nosound`. 0.50.73's `[av-mem]` dump showed the message Embree was writing: `Warning: SetThreadAffinityMask failed` (and `...SetThreadIdealProcessor failed`) to `std::cerr`. The `std::cerr` object (RCX, `msvcp140.dll+0xe4f10`) is all zeros: the builtin msvcp140 never constructed it for this caller, so the helper reads a null vbptr and faults. The warning exists because Embree pins worker threads to core numbers it takes from the emulated CPUID topology (SMT threads included, more than the 9 processors reported), and `NtSetInformationThread(ThreadAffinityMask)` answered STATUS_INVALID_PARAMETER when the mask had no bit in the system mask.

**Change.** `build/ntdll-unix/thread_ios.c`: (1) a mask with no valid processor is accepted and not applied (`[affinity] 0037 ...`, first six logged); (2) the old mask reported by ThreadBasicInformation / ThreadAffinityMask is the system mask when the stored one is empty (kernel32 returns it from SetThreadAffinityMask and 0 reads as failure). Nothing is pinned on iOS either way.

**Rebuild.** `tools/rebuild_ntdll_object.sh thread` (the script now knows `thread`), copy the library over `vendor/Madeira/app/Madeira/libntdll_unix.a`, restage.

**Not fixed.** `std::cerr` of the builtin msvcp140 stays unconstructed for a module that does not run `ios_base::Init`; any other message printed that way would crash the same way.

**0.50.74 result and 0.50.75.** CS2 on engine r7 still crashed at the same place (after ~212 s this time instead of ~110 s) and no `[affinity]` line was logged, so a mask with no valid processor was not what failed. Embree's text (`SetThreadAffinityMask failed`, not `SetThreadGroupAffinity`) means it took its legacy branch and `SetThreadAffinityMask(thread, 1 << n)` returned 0, which in kernel32 is: `NtQueryInformationThread(ThreadBasicInformation)` failing, or `NtSetInformationThread(ThreadAffinityMask)` failing, or the old mask in the basic information being 0. 0.50.75 also accepts ANY refusal of the server's `set_thread_info` for the affinity (nothing is pinned on iOS either way), and logs: the first twelve `NtSetInformationThread(ThreadAffinityMask)` requests (`handle length data system`), server refusals (with the status), failures of `ThreadBasicInformation`, and an empty stored mask. If the crash persists, those lines say which step it is.
