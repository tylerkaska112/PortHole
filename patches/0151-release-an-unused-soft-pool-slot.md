# 0151 ntdll: VirtualFree of a soft 32 GB slot that was never used now succeeds

`build/ntdll-unix/virtual_ios.c` (`NtFreeVirtualMemory`, new `ios_soft_release`). BeamNG.drive (Steam, 2026-10-16, 0.50.383, a user's iPhone log) reserves 32 GB with nothing else in the call. No real hole is that big (`[va-scan] FAILED ... File exists`), so the engine answers with a *soft* slot (`[soft-pool] GRANTED soft 0x7400000000 ... unbacked`), which is only a row in `ios_soft[]` with no view and no mapping. The game releases it at once with `VirtualFree(base, 0, MEM_RELEASE)`; with no view that was `STATUS_MEMORY_NOT_ALLOCATED` (0xc00000a0, `[free-refused] ml1285 #2`), the game treated it as fatal and executed `ud2` (`[task-exc] BREAKPOINT`, `[int3-guest] ... 0f 0b`), and the run ended. The wineserver `req_cancel_async` null dereference about 15 s later in the same log is teardown fallout, not the cause.

Fix: a MEM_RELEASE with size 0 at the exact base of a soft slot nobody committed in (no commits, no committed bytes, no collisions, not a cage slot) removes the row (the table has only 8 places) and returns success with the slot's size. A slot with commits keeps the old answer, so the PartitionAlloc/V8 pools are untouched. Log line: `[soft-pool] 0151 RELEASED soft 0x... +32768MB`.
How to test: start BeamNG.drive from Steam; look for the RELEASED line and for no `[free-refused]` at 0x7400000000. UNKNOWN: what the game does after a successful release (it may reserve again by its own scheme and hit the next limit). Untested on a device.
Library: `gl-lib-0151` (ntdll `virtual` object rebuilt on `gl-lib-merge`'s library; the other archives are the merge's).
