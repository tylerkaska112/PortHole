# 0070 startup timeline of the busiest guest thread (diagnostic, Black Ops 3 only)

`server_ios.c`, `process_ios.c`. The offline emulation (0069 dump, Unicorn) showed that Black Ops 3's spin is a closed loop of 41 states that reads nothing but a few constants on its own stack frame: no register or stack word I changed made it leave, and it never reads kernel32. So the cause is upstream: something sent the game into this loop. `ios_timeline_main` starts when a program called `blackops3.exe` is created (`ios_blackops3_started`, set in `process_ios.c` where 0066 looks for the name) and, every 50 ms for 150 s, reads the live registers of the thread with the most CPU. When its (rsp, rbp) pair changes it saves 0x400 bytes of stack from rsp-0x40 into `Documents/bo3-timeline/s<n>.bin` and a line into `index.txt` (ms, thread, cpu %, rip, rsp, rbp, rax, rcx, rdx, file). At most 600 snapshots. The 0068 dump is now also limited to Black Ops 3: before, any game with a guest thread at 100% CPU would have written about 100 MB.
