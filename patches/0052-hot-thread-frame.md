# 0052 - FEX-frame registers and code of a hot thread (diagnostic)

Follow-up to 0051. With the module order fixed (0045..0050) Black Ops 3 spins for 8+ minutes at ~100% CPU (`[cpu-split]`/`[rip-profile]`: the dispatcher returns to the same guest block, `0x7059280000+0x2a8fa80` range, 64 B `... mov rax,[rbp+0x80]; mov edx,[rax]; mov [rbp+0x3c],edx; mov eax,[rax+4]; mov [rbp+0x40],eax; add qword [rbp+0x80],8; mov dword [rbp+0x8c],1; jmp ...`), the host-register dump of 0051 is not reliable inside JIT code. `server_ios.c`: for a >= 90% CPU guest thread, `[thread-regs] 0052 frame rip= RAX=... R15=` read from the FEX frame (x28+0x18 rip, x28+0x20 gregs), `code from rip-0x40` (0x180 bytes) and `*REG=<value>: 48 bytes` for every pointer-looking register (RBP+0x20 for RBP). Cap 40 lines per run.
