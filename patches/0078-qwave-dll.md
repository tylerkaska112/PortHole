# 0078 qwave.dll added to the ARM64EC system libraries

Rust through Steam (0.50.129, 2026-10-06, 9 minutes, texture/shadow settings lowered, swap 10 GB wide + SWAP_FEX): memory was steady around 2.3-3.1 GB, then jumped to 5.8-6.1 GB in the last minute and iOS ended the app. From 04:11:55 the log has 291 lines `import_dll Library qwave.dll (which is needed by ...\RustClient_Data\Plugins\x86_64\discord_partner_sdk.dll) not found`, accelerating (14, 39, 106, 120 per 2000 log lines): Rust's Discord plugin is loaded again at every call, each load maps the image, fails on its missing import and does not give the memory back (the same pattern as The Forest's OVRPlugin.dll, docs/GAME_FIXES.md). The guest band grew from 1.9 to 3.2 GB dirty in that minute.

`qwave.dll` (Windows QoS) built from the pinned Wine submodule (`DEST=... bash vendor/Madeira/build/wine-pe/build-modules.sh qwave`; ARM64EC, 590 KB; QOS* exports; imports only ucrtbase, kernel32, ntdll) into `vendor/Madeira/app/Madeira/arm64ec-windows/`; listed in `docs/REBUILT_BINARIES.sha256`. The Discord plugin can load once and later calls reuse it. Not verified on a device: the plugin may import something else that is missing (it would show in the same trace).
