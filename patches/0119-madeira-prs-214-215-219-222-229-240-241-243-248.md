# 0119 Open Madeira pull requests taken: 214, 215, 219, 222, 229, 240, 241, 243, 244, 248

Madeira's `main` has not moved since our pin (`48f9764`, 2026-10-07); these are the open pull requests of <https://github.com/willfaust/Madeira> that were chosen on 2026-10-12.
Their native parts are applied to `vendor/Madeira` (recorded in the `.patch` next to this file, as a diff against the tree before); the Swift UI of Madeira's own app is not part of Porthole, so
what each one did for the user is re-done in `app/Sources` (listed below). Everything is **not verified on a device**.

| PR | What | Where it landed |
|---|---|---|
| 214, 215 | `PrefixExtractor.c`: refuse `..`/absolute names and a bad or negative tar size | vendored glue (`app/Runtime/PrefixExtractor.c`) |
| 219 | Low-RAM swap tier: stores that cross a 16 KB alias page are split per page (ml1289), freezes in `server_ios.c`/`signal_arm64_ios.c` | `libntdll_unix.a` objects virtual, signal_arm64, server |
| 222 | Desktop mouse-look and iPad pointer lock: cursor visibility mirrored to the metadata, raw/fallback button sources | `libwin32u_unix.a` `driver.o`, Winios; the Swift half (`HardwareInput.swift`) has no counterpart in Porthole |
| 229 | Final Fantasy Tactics: `oversize-reserve` (16 GB real part of a 64 GB+ reserve) and `fft-arena-patch`; madeira-d3d12 ml1300-ml1310 (command list 8, empty pipeline library, view-list lock) | `virtual_ios.c` (two hunks done by hand), `madeira_d3d12.dll`/`d3d12.dll` rebuilt (`ec-out`, linked against the shipped `winemetal.dll`); per-game switch "Large memory reservations" (`GameEngine.largeReservations`) |
| 240 | A launcher that relaunches itself gets the fixed exe base after the first copy exits | `virtual_ios.c`, `process_ios.c` |
| 241 | ARM64EC farm: `tbs`, versioned D3DX9/10, D3DCompiler, XAudio2, X3DAudio, XAPOFX, `d3d10`, `d3d10_1`, `wmadmod`, `winegstreamer` (not `wintypes`: ours from 0074 stays), the 64-bit WMA decoder table | 67 DLLs in `app/Madeira/arm64ec-windows`, `winegstreamer_unixlib_ios.c` (needed `winegstreamer` in `tools/rebuild_ntdll_object.sh`) |
| 243 | Census mode 2: windows first shown minimized after the starting screen are still restored | Winios; `SessionController.stopLaunchWatch(keepRestoring:)` |
| 244 | DXMT census throttle | `EngineLaunch.apply` exports `DXMT_CENSUS_THROTTLE=1` unless madeira.cfg sets it |
| 248 | Twelve multi-process and privacy fixes (own exiting flag for the first process, TlsFree clears only its own process, decommit zeroes only committed pages, stuck-fault breaker per thread, INET poll cache, RWX writes by the kernel/wineserver, no key presses and no credential-like arguments in the log) | `env_ios.c`, `process_ios.c` (one hunk by hand), `server_ios.c`, `signal_arm64_ios.c`, `virtual_ios.c`, `driver_ios.c`, `fd_ios.c` (wineserver), `madeira_redact.h`, Winios, `WineProcessBridge.m`. Its companion `willfaust/wine#28` (getsockopt, /dev/urandom, ReadFileScatter into RWX buffers) is NOT in our Wine tree. |
| 210 | x87 toggle | `EngineLaunch.apply`: Off exports `FEX_X87REDUCEDPRECISION=0` (the WoW64 backend defaults it to ON) |

Not taken because Porthole has it already: 246 (thermal guard in `PowerManager`), 237 (Steam Cloud download switch), 216/223 (our own Steam client).
