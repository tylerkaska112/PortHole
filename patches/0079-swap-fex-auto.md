# 0079 swap tier: the emulator's arena joins only when the footprint is high (automatic mode)

`virtual_ios.c` (`ios_swap_fex_arena_ok`). `MADEIRA_SWAP_FEX=1` (0073) backs the emulator's arena with the swap file from the start. It keeps the footprint low (Sons of the Forest: 4 GB held in the file for 2.4 GB of footprint) but slows the game, and Rust's server join (2026-10-06: 3.5 -> 5.8 GB in one minute) showed the opposite failure without it.

`MADEIRA_SWAP_FEX=auto` (Settings > Engine options > Swap also keeps the emulator's memory > Automatic): nothing is backed until the app footprint (`ios_last_footprint_mb`, which the pool warmer already publishes every 250 ms; no new measurement) reaches `MADEIRA_SWAP_FEX_AT_MB` (default 3000 MB, minimum 512). From then on, one-way, what the emulator allocates goes to the file, so the memory the game needs next (a world loading, new threads, new translated code) does not push the app over iOS's limit. What was allocated before stays where it is. Needs `MADEIRA_SWAP_COVERAGE=wide` and a swap size (`swap-mb`, per game on its Engine page) big enough: 16000 worked for Rust. Logs `[swap] 0079 auto: ...` at the start and once when it trips. Without the variable nothing changes.
Not verified on a device. What to watch: the trip line's time, the `[swap] ml1077 stats` file-backed MB growing after it, `refused` staying 0, the frame rate before and after.
